# Step 5 — Open the PR

> **Time budget:** 6 minutes • **Skill:** `/ai-pr`

## What you will learn

- How the framework auto-branches, stages, commits, and pushes — all with hard gates.
- Why the PR body comes from the spec and plan, not from your memory.
- How CI is watched and what happens on green.

## The command

```
/ai-pr
```

No argument. The skill reads `spec.md` + `plan.md` + your unstaged changes.

## What is happening

`/ai-pr` is a 16-step pipeline. The greatest hits:

1. **Auto-branch.** If you are on `main`, it creates `feat/<slug>` (or `fix/` for fix specs) and switches to it. No risk of accidentally pushing to main.
2. **Selective staging.** Stages only the files that match the spec — no surprise additions.
3. **Pre-commit gate.** Runs `ai-eng gate run --cache-aware --json --mode=local`:
   - Wave 1: fixers (ruff, prettier) serial.
   - Wave 2: checkers (gitleaks, semgrep, pip-audit) parallel.
   - Hot-path budget: < 1 second.
4. **Conventional Commit composition.** Subject from spec title, body explains *why* (from spec goal), trailers cite spec ID.
5. **Pre-push gate.** Residual checks before push. Hot-path budget: < 5 seconds.
6. **3-lane concurrent dispatch.**
   - Lane A: docs (CHANGELOG, README, solution-intent).
   - Lane B: portal quality gate.
   - Lane C: spec lifecycle update.
7. **Create or update PR** via `gh pr create`. PR body composed from `pr_body_compose.py`.
8. **Enable auto-complete.** `--squash --delete-branch` once CI passes.
9. **Watch loop.** Polls CI every 1–3 minutes until green.
10. **On merge** runs `spec_lifecycle.py mark_shipped`:
    - Appends 7-column row to `.ai-engineering/specs/_history.md`.
    - Resets `spec.md` and `plan.md` to placeholders.
    - Walks state through DRAFT → APPROVED → IN_PROGRESS → SHIPPED.

## What you will see

```
[BRANCH] creating feat/spec-NNN-status-json-format from main
[STAGE] src/myapp/cli.py, tests/test_cli.py
[GATE pre-commit] ruff (PASS, 0.12s) · gitleaks (PASS, 0.08s) · semgrep (PASS, 0.31s)
[COMMIT] feat(cli): add --format flag to myapp status
[GATE pre-push] pip-audit (PASS, 0.42s)
[PUSH] origin/feat/spec-NNN-status-json-format
[PR] opened #1 — https://github.com/<you>/ai-engineering-workshop/pull/1
[AUTO-COMPLETE] enabled (squash + delete branch)
[CI] watching... build (queued) · tests (running)
[CI] ✓ build · ✓ tests · ✓ lint
[MERGE] PR #1 squash-merged to main
[LIFECYCLE] spec-NNN → SHIPPED, _history.md row appended
[CLEANUP] spec.md and plan.md reset to placeholders
```

## What to watch for

- **The PR is created on YOUR fork**, not on `arcasilesgroup/ai-engineering-workshop`. If your local has the original as `origin`, run `gh repo fork --remote` before `/ai-pr` so you have a forkable target. (Easier: clone your fork from the start.)
- **CI watch is real.** The skill polls until merged. If CI fails 3 times on the same check, it escalates to you with the failure diff.
- **The PR body is auto-composed.** It includes the spec goal, the test plan from `plan.md`, and a checklist of gates that passed. Do not edit it by hand — re-run `/ai-pr update` to regenerate.

## What if I do not want to actually push to GitHub?

```
/ai-pr --draft
```

`--draft` opens a draft PR and skips the watch-and-merge loop. Useful for the workshop if you do not want to spam the org with workshop PRs.

For a totally local rehearsal:

```
/ai-pr --only commit
```

This runs only the commit pipeline (stage + gate + commit). No push, no PR.
