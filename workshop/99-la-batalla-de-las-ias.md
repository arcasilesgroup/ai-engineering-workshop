# Ejercicio final — La Batalla de las IAs

> Reto final del workshop.

## Objetivo

Usar ai-engineering para convertir un reto abierto de 60 minutos en una demo funcional, explicable y revisable.

El grupo elige uno de dos retos:

- [Reto A — App de lectura social](la-batalla-de-las-ias/reto-a-lectura-social.md)
- [Reto B — App de clubes de lectura](la-batalla-de-las-ias/reto-b-clubes-lectura.md)

## Cadena obligatoria

```text
/ai-start
/ai-brainstorm "convert this challenge into an approved MVP spec for a 60-minute demo"
/ai-plan
/ai-build
/ai-review
/ai-explain "what did we build and where are the riskiest assumptions?"
```

## Reglas del reto

- Demo funcional y navegable, no producto final.
- Stack libre.
- Datos dummy permitidos.
- Sin autenticación real salvo que el equipo la tenga ya preparada.
- Una persona externa debe poder seguir el flujo principal sin explicación verbal.
- El criterio de éxito pesa más que la cantidad de features.

## Criterio de evaluación

| Criterio | Qué buscamos |
|---|---|
| Claridad del MVP | El spec corta scope y evita feature creep. |
| Uso de ai-engineering | Hay spec, plan, decisiones y review; no solo vibe coding. |
| Demo navegable | El flujo principal funciona de punta a punta. |
| Diseño de interacción | La app se entiende rápido y usa la marca con criterio si decide usarla. |
| Explicabilidad | El equipo puede explicar qué construyó, qué no y qué riesgos quedan. |
